# Architecture

How this repo is organised so it can grow from Thai against English into a maintained
benchmark without a rewrite. This file describes the code as it is; `LOG.md` records what
was run.

## Design goals

1. **Every published number traces back to a raw file and a command.** Nothing is typed by hand.
2. **Adding a model or a language is a one-line change** in a registry file, not new code.
3. **Anyone can rerun it** with one command and get the same numbers (or see exactly why not).
4. **Results are append-only.** A new run adds a dated result set; old ones stay for the history chart.
5. **Small and readable.** Python standard library where possible, a static site, no framework.

## Pipeline

```
registry/*.toml ──┐                                          (site/data.json ─► card ─► share cards)
                  ▼
FLORES-200 ─► prepare ─► count ─► analyze ─┐
 (download,   (NFC,      (one      (premium, │
  checksum)    align)     counter   CI)      ├─► results/ ─► site ─► site/data.json ─► site/index.html
                          per tokenizer      │   (dated,     docs ─► README.md, README.th.md,
                          family)            │    never              docs/methodology.md
                             ▲               │    overwritten)
                             └── verify      │
official pricing pages ─► prices ─► cost ───┘
Bank of Thailand rate ──┘
```

Each stage reads files and writes files. No stage calls another stage's internals, so
any stage can be rerun or replaced on its own. Two further commands add evidence to
`results/`: `compare` (FLORES-200 against FLORES+) and `billing-check` (Claude
`count_tokens` against billed usage; the only command that spends money).

`site` and `docs` are the only way numbers reach a page or a document: both read
`results/latest.json` and the files it points to, check that those files belong together,
and stop if they do not. `docs` reuses the checked reading in `site.py`, so the documents
and the page always show the same values.

## The counter interface

Every tokenizer family is measured through the same small interface, so the analysis
never knows where a count came from:

- `count(texts: list[str]) -> list[int]` returns **content tokens only** for each text.
  Local tokenizers add no special tokens. API counters subtract the fixed overhead they
  measured on a minimal message, and report that overhead.
- `describe() -> dict` returns what was measured: model id, tokenizer or encoding,
  library version or API version, file hashes where they exist, UTC time.
- A counter that cannot run (missing key, gated repo) raises a `Blocked` error with the
  real reason. The run records it as blocked. It is never replaced by a guess.
- API counters checkpoint per sentence and resume, with backoff on rate limits.

## Results contract

- Raw file: one row per sentence × language × tokenizer, with run date, dataset, model id,
  tokenizer, library, characters, tokens. This is the only source for every table.
- Summary: premium (TH ÷ EN, within one model), 95% bootstrap CI over sentence pairs,
  **absolute** Thai tokens and tokens per 1,000 Thai characters (for comparing across models).
- One raw file per source per run: `counts_<date>_<source>.csv`, where source is `open`
  (local tokenizers), `anthropic`, `gemini` or `openai`. Each has a `.meta.json` beside it
  (versions, file hashes, measured overhead, blocked list). `analyze` merges the sources.
  A model added later is its own set, `counts_<date>_<source>-<label>.csv`.
- A model marked `sample_of` in the registry is counted on a fixed random sample only and is
  assigned to a fully measured model if every sampled count is identical.
- Prices: `prices_<date>.json` (official pages, page hashes, exchange rate). Costs:
  `costs_<date>[_<label>].{csv,json,md}`, with the hashes of the summary and prices they used.
- The registry may pin a Hugging Face repo `revision`, so a rerun measures the same
  tokenizer file. Measuring a newer tokenizer is an explicit registry change.
- `results/latest.json`: the file names of the newest set (counts, verification, summary,
  prices, costs, billing check). `ttt site` and `ttt docs` start from this file; the web page
  itself reads only `site/data.json`.
- The code refuses to overwrite an existing result file.
- Published result files are never edited. A correction is a new dated run plus a line in `LOG.md`.

## What is deliberately left out

- No database, no web framework, no build step for the site (`ttt site` writes one JSON file;
  the page is served as it is).
- No answer-quality evaluation. This measures token cost only, and says so everywhere.
- No dataset sentences in git (FLORES asks that the text not be republished in scrapeable form).
- No keys in files, ever. Keys come from environment variables (GitHub Actions secrets later).

## Growth path

| Version | What changes | Code change needed |
|---|---|---|
| v1.0 | Thai vs English, all major tokenizers, baht costs, site, articles | this architecture |
| v1.1 | Other Southeast Asian languages | lines in `languages.toml` |
| v1.2 | New model released | a line in `models.toml`, rerun |
| v1.3 | Scheduled reruns + history chart | `measure.yml`, site reads older result sets |
| v2.0 | `pip install` + "measure your own text" command, technical report with DOI | packaging + docs |
